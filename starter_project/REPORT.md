# REPORT по Практической работе №8

**Вариант 7.** Изменяемый аспект — минимальная длина причины отклонения. Значение: **40**.

## 9. Анализ ошибки из фрагмента
**Фрагмент:** `public void setStatus(TripStatus status) { this.status = status; }`
**Ошибка:** Открытый метод `setStatus` позволяет внешнему коду менять статус заявки произвольно (например, перевести заявку из `DRAFT` сразу в `COMPLETED`), полностью обходя бизнес-логику и проверки.
**Исправление:** Мы удалили `setStatus` и заменили его на доменные методы (`submit`, `approve`, `reject`), каждый из которых проверяет допустимость перехода.

## 10. Результаты граничных проверок
| Проверка | Что необходимо подтвердить |
|---|---|
| корректное типовое значение | Создание заявки с датами 2026-10-10 и 2026-10-12. Ожидается: успешное создание. |
| нижняя граница (включение) | `reject` с причиной ровно 40 символов. Ожидается: успешное отклонение. |
| нижняя граница (исключение) | `reject` с причиной 39 символов. Ожидается: `IllegalArgumentException`. |
| верхняя граница | `complete` в день, когда `today == end`. Ожидается: успешное завершение. |
| пустое или отсутствующее значение | `reject(null)` или `reject("")`. Ожидается: `IllegalArgumentException`. |
| значение неверного формата | Не применимо (причина задается строкой, статус — enum). |
| повтор или конфликт данных | `submit()` из статуса `SUBMITTED`. Ожидается: `IllegalStateException`. |

## 11. Собственные формулировки
**Какая проверка защищает программу от наиболее вероятной ошибки?**
Проверка `status != TripStatus.SUBMITTED` в методе `approve` и проверка длины причины в методе `reject`.

**Какой метод или класс содержит ключевое бизнес-правило?**
Класс `BusinessTrip`. Все переходы состояний (правила конечного автомата) инкапсулированы в его доменных методах.

**Как Activity-диаграмма отражает один конкретный участок кода?**
Ромб «Переход допустим» соответствует проверкам `if (status != ...)` в каждом методе класса `BusinessTrip`.

**Какое изменение требования затронет минимальное количество классов?**
Изменение длины причины (вариант 7). Достаточно изменить одну константу `MIN_REASON_LENGTH` в классе `BusinessTrip`.
